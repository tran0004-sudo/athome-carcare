# VIP 계약 원장 운영 방법

## 개념과 화면
- 관리자 로그인 → **월 회원** → 상단 **VIP 계약·월별 횟수 관리**에서 계약을 등록합니다.
- 고객 번호(010 11자리), 이름, 차종, **월 2회 또는 월 4회**, 시작일, 만료일, 정기관리 기준일을 입력합니다.
- 계약 상태는 운영 / 일시중지 / 종료 중 선택합니다. 날짜가 지나면 자동으로 화면상 만료로 표시됩니다.
- **이용 주기**는 계약 시작일을 기준으로 매월 갱신됩니다(예: 10월 10일 시작이면 다음 주기는 11월 10일 시작). 달 마지막 날은 해당 월의 말일을 사용합니다.
- **잔여 횟수 = 이번 주기 한도 2회/4회 – 이 계약에 연결된 완료 작업 수**, 최소 0회. 다음 주기가 시작되면 새 주기로 계산합니다. 미사용 횟수는 이월하지 않습니다.
- **권장 관리일**은 관리자 지정 관리 기준일에서 월 4회는 7일, 월 2회는 14일 간격으로 계산한 일자이며 예약 확정 날짜가 아닙니다. 계약 만료일 이후엔 표시하지 않습니다.
- 관리자가 예약을 **완료** 처리한 후 VIP 계약 관리에서 해당 예약을 선택해 '이용 1회 연결'해야만 차감됩니다. 신규 가입/상담 예약을 완료 처리했다는 이유만으로 자동 차감되지 않습니다.
- 연결된 방문은 필요 시 '연결 해제'하여 횟수를 복원할 수 있습니다. 같은 예약을 두 계약에 연결하는 것은 DB에서 차단합니다.
- 고객 **내 관리** 화면에서 본인인증 후 계약별 이용 주기, 사용/잔여 횟수, 만료일과 권장일을 확인합니다. 실제 확정 세차 예약이 있으면 그 예약일이 우선 표시됩니다.

## 데이터 및 권한
- `public.vip_contracts`: 계약(전화번호·월 횟수·시작/종료·관리 기준일·상태)
- `public.vip_visit_links`: 실제 완료 예약과 계약을 연결한 원장
- `public.vip_contract_snapshot(uuid)`: DB 단일 기준일(Asia/Seoul)에 맞춰 계약별 주기·잔여 횟수 계산
- `public.get_my_vip_contracts()`: SMS 본인인증 완료된 고객의 번호로만 계약 조회. 입력 전화번호 인자를 받지 않음
- 원장 테이블은 RLS상 관리자(Owner)만 읽기·쓰기 허용하며 공개 조회/가입은 금지합니다.
- 고객용 마이페이지는 잔여 횟수 RPC를 사용하고, 관리자 메모/전화번호/차량번호 등은 반환하지 않습니다.
- 관리자만 세차 완료 예약을 계약에 연결할 수 있고, 연결 시 서버가 번호 일치·작업 완료 여부·계약 기간을 검증합니다.

## 최초 등록 및 기존 고객 이관
- **기존 예약 기록으로 계약을 자동 생성하거나 차감하지 않습니다.** 운영자가 고객의 실제 계약 정보를 확인한 뒤 계약을 등록해야 합니다.
- 기존 완료 방문을 소급해서 반영하려면 동일 고객 번호·계약 유효기간에 속하는 예약을 관리자 화면에서 명시적으로 연결합니다.
- 잔여 횟수는 완료 작업을 계약에 연결하기 전까지 실제보다 높게 표시될 수 있으므로 운영 시작 전 기존 계약을 정리해야 합니다.
